Лабораторная 1: React + TypeScript + Vite

Как устроен проект StudyFlow, почему TypeScript важен на этапе сборки и как ответить на защите на 10/10.

Ошибки новичка
  • Коммитить node_modules/ или dist/ в репозиторий Git
  • Думать, что TypeScript работает внутри рантайма браузера
  • Запускать сборку без проверки типов tsc -b
  • Оставлять дефолтный счетчик и SVG-иконки Vite
Стандарт курса
  • Строгий .gitignore и чистый запуск через npm ci
  • TS проверяет типы на этапе сборки, защищая от runtime ошибок
  • Скрипт "build": "tsc -b && vite build" гарантирует надежность
  • Семантический экран с адаптивной CSS-разметкой
Архитектурная цепочка монтирования и сборки

Изолированный Frontend
Код клиентской части находится в подпапке frontend/. Корневой репозиторий готов к добавлению backend/ в ЛР 8.

Вопросы для защиты перед Бричагом Д.В.

1. Как связаны index.html, main.tsx и App.tsx? +
index.html — точка входа браузера с контейнером <div id="root">. Скрипт main.tsx находит этот элемент и вызывает createRoot(...).render(<App />), монтируя компонент App.tsx в реальное дерево DOM.
2. Чем JSX отличается от обычной HTML-разметки? +
JSX — синтаксический сахар над вызовами JavaScript-функций (React createElement). В отличие от HTML, в JSX классы именуются className, события — в camelCase (onClick), переменные вставляются в фигурных скобках {}, а все теги обязаны явно закрываться.
3. Какую ошибку в вашем проекте обнаруживает TypeScript? +
Компилятор tsc проводит статический анализ типов. Если переменной appTitle: string присвоить число, tsc -b выбросит ошибку TS2322 и заблокирует создание production-сборки в папке dist/.
4. Чем отличаются dev, build и preview? +
dev отдает нативные ES-модули и выполняет Fast Refresh (HMR) на лету без сборки файлов на диск. build запускает строгий анализ типов и собирает минифицированные файлы в dist/. preview запускает локальный HTTP-сервер для проверки собранного dist/.
5. Зачем нужен package-lock.json и почему node_modules не хранится в Git? +
node_modules содержит тысячи тяжелых платформозависимых файлов, которые легко восстановить командой npm ci. package-lock.json фиксирует точные версии и контрольные суммы дерева пакетов, гарантируя воспроизводимость.
6. Чем отличаются commit и push? +
git commit фиксирует снимок изменений в локальной базе данных репозитория на компьютере разработчика. git push передает накопленные коммиты на удаленный сервер (GitHub).
7. Что уже работает в приложении и что добавит ЛР 2? +
Сейчас работает каркас приложения с типизированным заголовком, семантической версткой и заглушкой списка заданий. ЛР 2 добавит разделение на независимые компоненты, клиентскую маршрутизацию страниц и динамические свойства (props).
