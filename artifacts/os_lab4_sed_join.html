          1. Архитектура потокового процессора sed
        

        Pattern Space vs Hold Space
      


      

        Редактор sed (Stream Editor) — это не интерактивный текстовый процессор, а детерминированный потоковый автомат. Он считывает входящие байты построчно через stdin, выполняет цикл инструкций и передает поток в stdout без создания промежуточных файлов на диске.
      


      
      

        
      


      
      

        

          
Цикл выполнения (Execution Cycle)

          

            1. Read: Считывается 1 строка, удаляется символ 
, строка помещается в Pattern Space.

            2. Match: Проверяются селекторы адресов: номер строки (1, $), диапазон (5,10) или регулярное выражение (/PATTERN/).

            3. Execute: При совпадении адреса применяются команды.

            4. Flush: Содержимое Pattern Space выводится в stdout (если нет ключа -n), буфер очищается и цикл повторяется.
          

        


        

          
Команды буфера Hold Space

          

            • h (Hold) — перезаписывает Hold Space содержимым Pattern Space.

            • H — дописывает к Hold Space через символ перевода строки.

            • g (Get) — перезаписывает Pattern Space содержимым Hold Space.

            • G — дописывает к Pattern Space через перенос строки.

            • x (Exchange) — атомарно меняет содержимое двух буферов местами.
          

        


        

          
Многострочные команды & Метки

          

            • N — дочитывает следующую строку в Pattern Space через 
.

            • D — удаляет первую подстроку до 
 и запускает цикл заново.

            • P — печатает первую подстроку до 
.

            • :label, t label — условный переход (ветвление), если предыдущая замена s/// завершилась успешно. Делает sed Тьюринг-полным!
          

        

      

    


    
    

      

        

          
          2. Реляционная алгебра join и ловушка сортировки
        

        Sort-Merge Algorithm
      


      

        Утилита join выполняет реляционное соединение строк из двух текстовых файлов на основе совпадения общего ключевого поля. Это прямой аналог операторов INNER JOIN, LEFT JOIN и OUTER JOIN в языке SQL.
      


      

        

          
Алгоритм двух указателей (Sort-Merge)

          

            В отличие от СУБД, утилита join не строит хэш-таблиц в памяти. Она одновременно перемещает два указателя по обоим файлам строго в одном направлении. Сложность слияния составляет всего O(N + M).


            Следствие: если хотя бы один файл нарушает лексикографический порядок, указатель «проскочит» строку и join аварийно остановится с ошибкой join: input is not in sorted order, потеряв данные.
          

        


        

          
Опасность локали: LC_ALL=C

          

            Утилита sort по умолчанию использует параметры локали системы (например, ru_RU.UTF-8), где регистр символов и знаки препинания группируются иначе, чем по чистым ASCII-кодам.


            Если sort отсортировал файл в UTF-8, а join сканирует его по байтам, возникнет скрытый сбой сопоставления. Всегда вызывайте:
            LC_ALL=C sort -k...
          

        


        

          
Смещение колонок в выводе join

          

            Главный подвох утилиты join: ключевое поле, по которому производилось сопоставление, ВСЕГДА автоматически становится первым полем ($1) в результирующей строке вывода!


            Все исходные индексы полей смещаются, поэтому при последующей передаче в cut -d' ' -f... или sed необходимо пересчитывать номера колонок!
          

        

      

    


    
    

      

        

          
          3. Анатомия конвейеров ядра Linux: pipefs и буферы
        

        Kernel Ring Buffer
      


      

        

          
Кольцевой буфер 64 КБ

          

            Символ | вызывает системный вызов pipe(2). Ядро Linux создает структуру кольцевого буфера в оперативной памяти псевдо-файловой системы pipefs объемом 64 КБ (16 страниц памяти). Никакие байты конвейера не сбрасываются на SSD или HDD.
          

        


        

          
Атомарность PIPE_BUF (4096 Б)

          

            Константа POSIX PIPE_BUF в Linux равна 4096 байт. Если писатель пишет порцию $\le 4096$ байт, ядро гарантирует неделимость: данные нескольких параллельных процессов никогда не перемешаются. Если блок больше 4 КБ — ядро может разбить его на куски.
          

        


        

          
Сигнал SIGPIPE & EPIPE

          

            Если читающий процесс (например, head -n 5) прочитал 5 строк и завершился, закрыв свой файловый дескриптор, то следующая попытка записи процессом-писателем вызывает генерацию сигнала SIGPIPE. Пишущий процесс немедленно завершается, предотвращая холостую работу процессора.
          

        

      


      
      

        
Архитектурный манифест: Решение задач агрегации в чистом Bash без awk

        

          
            

              Операция
              Запрещено кафедрой (awk)
              Легитимно: Чистый Bash 4+ / sed
            

          
          
            

              Группировка и сумма выручки
              awk '{sum[$1]+=$2} END {for(i in sum) print i, sum[i]}'
              declare -A rev; while read -r s a; do ((rev["$s"]+=a)); done < <(...); for s in "${!rev[@]}"; do echo "$s ${rev[$s]}"; done
            

            

              Сворачивание дубликатов строк
              awk 'last==$1 {val+=$2; next} {if(last) print last,val; last=$1; val=$2}'
              sed -E ':a; N; s/^([A-Z]+) ([0-9]+)\n\1 ([0-9]+)$/\1 \$((\2+\3))/; ta; P; D' | while read -r l; do eval echo "$l"; done
            

            

              Числовая фильтрация > N
              awk '$5 > 20000'
              while read -r a b c d t; do [ "$t" -ge 20000 ] && echo "$a $t"; done
