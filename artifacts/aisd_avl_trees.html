АВЛ-деревья и повороты балансировки

Интерактивный путеводитель по самобалансирующимся деревьям поиска: фактор баланса, малые и большие повороты (L, R, LR, RL) и строгие доказательства $O(\log n)$.

⚖️ 1. Зачем балансировать деревья поиска?

В обычном двоичном дереве поиска (BST) последовательная вставка возрастающих чисел (1, 2, 3, 4, 5) вырождает дерево в линейный список высотой $n$. Сложность поиска падает с $O(\log n)$ до катастрофического $O(n)$!

📐 Инвариант Адельсона-Вельского и Ландиса (1962)

Для каждого узла дерева высоты правого и левого поддеревьев отличаются не более чем на 1:

bf(x) = height(x.right) - height(x.left) ∈ {-1, 0, 1}

🚀 Гарантия высоты $O(\log n)$

Даже в худшем случае (деревья Фибоначчи) высота АВЛ-дерева строго ограничена формулой:

h < 1.44 · log2(n + 2)

Поиск, вставка и удаление строго гарантированы за $O(\log n)$!

🔄 2. Четыре типа поворотов балансировки

В АВЛ-дереве поворот — это локальная перелинковка указателей за $O(1)$, которая восстанавливает разность высот $\Delta h \le 1$ и строго сохраняет инвариант двоичного дерева поиска ($Left < Root < Right$).

💡 ELI5: Принцип «Качелей» и «Усыновления поддерева» (T2)

Представьте, что дерево висит на ниточке за узел $A$. Ветка перевесила. При повороте мы берём тяжелого потомка $B$, поднимаем его в корень, а старый корень $A$ опускаем вниз.
Куда девать внутреннее поддерево $T_2$, которое было у $B$? По инварианту BST: $A < T_2 < B$. Значит, у опустившегося узла $A$ как раз освободилось место с нужной стороны — $T_2$ идеально перевешивается к $A$ без единой коллизии ключей!

Случай LL (Left-Left)

Одинарный малый правый поворот (Single Right Rotation)

Пример чисел: [30, 20, 10]

Условие: $bf(A) = -2$ и $bf(B) \le 0$. Левый сын левого поддерева перевесил. Форма перекоса — прямая линия влево.

Пошаговая перелинковка указателей (3 действия):

  1. Запоминаем левого потомка: B = A->left и его правое поддерево T2 = B->right.
  2. Перевешиваем $A$ вправо от $B$: B->right = A.
  3. Отдаем сироту $T2$ левым сыном к $A$: A->left = T2.
Node* rotateRight(Node* A) { Node* B = A->left; Node* T2 = B->right; B->right = A; // A становится правым сыном B A->left = T2; // T2 переходит левым сыном к A updateHeight(A); // Сначала пересчитываем высоту опустившегося A updateHeight(B); // Затем нового корня B return B; // Возвращаем новый корень поддерева }
Случай RR (Right-Right)

Одинарный малый левый поворот (Single Left Rotation)

Пример чисел: [10, 20, 30]

Условие: $bf(A) = +2$ и $bf(B) \ge 0$. Правый сын правого поддерева перевесил. Форма перекоса — прямая линия вправо.

Пошаговая перелинковка указателей:

  1. Запоминаем правого потомка: B = A->right и его левое поддерево T2 = B->left.
  2. Перевешиваем $A$ влево от $B$: B->left = A.
  3. Отдаем сироту $T2$ правым сыном к $A$: A->right = T2.
Node* rotateLeft(Node* A) { Node* B = A->right; Node* T2 = B->left; B->left = A; // A становится левым сыном B A->right = T2; // T2 переходит правым сыном к A updateHeight(A); // Пересчет высоты A updateHeight(B); // Пересчет высоты нового корня B return B; // Возвращаем новый корень }
Случай LR (Left-Right)

Большой правый поворот (Left-Right Double Rotation)

Пример чисел: [30, 10, 20]

Условие: $bf(A) = -2$, но $bf(B) = +1$. Знаки разные! Форма перекоса — зигзаг («колено» влево-вправо).
Одинарный поворот здесь бесполезен! Требуется два шага: сначала выпрямить колено в прямую линию, а затем сбалансировать корень.

Анатомия двух фаз LR:

  • Фаза 1 (Малый левый вокруг левого сына 10): узел 20 поднимается, 10 становится его левым сыном. Зигзаг распрямляется в однородную палку влево.
  • Фаза 2 (Малый правый вокруг корня 30): узел 20 поднимается в глобальный корень, 10 слева, 30 справа. Дерево идеально сбалансировано!
Node* rotateLeftRight(Node* A) { A->left = rotateLeft(A->left); // Шаг 1: выпрямляем левое поддерево return rotateRight(A); // Шаг 2: вращаем корень вправо }
Случай RL (Right-Left)

Большой левый поворот (Right-Left Double Rotation)

Пример чисел: [10, 30, 20]

Условие: $bf(A) = +2$, но $bf(B) = -1$. Знаки разные! Форма перекоса — зигзаг («колено» вправо-влево).
Как и в случае LR, сначала внутренним поворотом распрямляем зигзаг в прямую линию RR, а затем левым поворотом корня балансируем дерево.

Анатомия двух фаз RL:

  • Фаза 1 (Малый правый вокруг правого сына 30): узел 20 поднимается, 30 становится его правым сыном. Зигзаг выпрямляется в однородную палку вправо.
  • Фаза 2 (Малый левый вокруг корня 10): узел 20 поднимается в глобальный корень, 10 слева, 30 справа. Дерево идеально сбалансировано!
Node* rotateRightLeft(Node* A) { A->right = rotateRight(A->right); // Шаг 1: выпрямляем правое поддерево return rotateLeft(A); // Шаг 2: вращаем корень влево }
Шпаргалка к экзамену

Сводная матрица решений балансировки

Запомните простое правило: Одинаковые знаки корня и сына — малый поворот. Разные знаки — большой двойной поворот!

⚡ 4. 30-секундные ответы на устном экзамене

Вопрос: Почему АВЛ-дерево балансируется по высоте, а не по числу узлов?

Ответ: Балансировка по количеству узлов (весовая балансировка) при каждой вставке или удалении может требовать глобальной перестройки всего дерева за $O(n)$. Балансировка по высоте ($|bf| \le 1$) локализует дисбаланс: при вставке требуется максимум один поворот (малый или большой) вдоль пути подъема к корню, что гарантирует работу за $O(\log n)$.

Вопрос: Как по коэффициентам баланса понять, нужен малый или большой поворот?

Ответ: Смотрим на знаки коэффициентов баланса родителя и проблемного потомка:
• Одинаковые знаки ($+2$ и $+1$ либо $-2$ и $-1$) — перекос в одну сторону (палка), выполняется одинарный поворот.
• Разные знаки ($+2$ и $-1$ либо $-2$ и $+1$) — зигзаг («колено»), выполняется двойной поворот.
