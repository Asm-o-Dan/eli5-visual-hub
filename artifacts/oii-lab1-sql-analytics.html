🏪 3. Анатомия базы данных Northwind (Метафора склада)

Представь себе оптовую компанию (Amazon или оптовый склад продуктов). Вся деятельность разделена на логические таблицы:

❌ Ловушка 1: Ключевое слово ORDER

Слово ORDER в языке SQL зарезервировано под команду сортировки (ORDER BY). Если написать SELECT * FROM Order, база выдаст ошибку синтаксиса. Нужно всегда писать в кавычках: FROM "Order".

❌ Ловушка 2: Скидки покупателям

Если считать выручку как Price * Quantity, ответ будет завышен на $6 миллионов! Клиенты получали скидку (поле Discount), поэтому формула: Price * Quantity * (1 - Discount).

📝 4. Пошаговый ход решения 5 задач (Вариант №2)
ЗАДАНИЕ 1
Какой сотрудник обработал наибольшее количество заказов?
Ход мысли:
Каждый заказ оформляет менеджер. В таблице "Order" есть поле EmployeeId (1, 2, 3...). Но там нет фамилий. Чтобы узнать имена, мы объединяем (JOIN) таблицу сотрудников Employee с заказами по общему полю Employee.Id = Order.EmployeeId, группируем по каждому менеджеру и считаем заказы через COUNT(o.Id). 
SELECT 
    e.Id AS EmployeeId,
    e.LastName,
    e.FirstName,
    e.Title,
    COUNT(o.Id) AS OrdersProcessed
FROM Employee e
JOIN "Order" o ON e.Id = o.EmployeeId
GROUP BY e.Id
ORDER BY OrdersProcessed DESC;
🏆 Лидер: Janet Leverling (ID=3) — 1 964 заказа
ЗАДАНИЕ 2
Какая категория продуктов принесла наибольшую выручку?
Ход мысли:
Деньги лежат в деталях заказов OrderDetail, но там указан только ProductId. А название категории CategoryName лежит в таблице Category. Значит, строим реляционный мост из 3 таблиц: Category → Product → OrderDetail. Выручку считаем строго с учетом скидки: SUM(UnitPrice * Quantity * (1 - Discount)). 
SELECT 
    c.Id AS CategoryId,
    c.CategoryName,
    ROUND(SUM(od.UnitPrice * od.Quantity * (1.0 - od.Discount)), 2) AS NetRevenue,
    SUM(od.Quantity) AS TotalUnitsSold
FROM Category c
JOIN Product p ON c.Id = p.CategoryId
JOIN OrderDetail od ON p.Id = od.ProductId
GROUP BY c.Id, c.CategoryName
ORDER BY NetRevenue DESC;
💰 Лидер: Beverages (Напитки) — $93 616 392.93 (продано 3 099 261 шт.)
ЗАДАНИЕ 3
Сколько различных клиентов делали заказы?
Ход мысли:
В таблице "Order" всего 16 818 заказов. Но крупные магазины покупают товар десятки раз в год. Если просто посчитать строки COUNT(CustomerId), мы получим число покупок. Чтобы отсечь дубликаты и оставить только уникальных покупателей, используем оператор DISTINCT. 
SELECT COUNT(DISTINCT CustomerId) AS DistinctCustomers
FROM "Order";
👥 Ответ: 95 различных клиентов совершали покупки
ЗАДАНИЕ 4
Какая категория содержит наибольшее количество продуктов, заказанных хотя бы раз?
Ход мысли:
Обрати внимание на формулировку: вопрос не про количество проданных коробок, а про широту ассортимента (сколько РАЗНЫХ наименований товаров покупали). Мы связываем категории с заказанными товарами и считаем уникальные ID продуктов: COUNT(DISTINCT p.Id). 
SELECT 
    c.CategoryName,
    COUNT(DISTINCT p.Id) AS OrderedProductsCount
FROM Category c
JOIN Product p ON c.Id = p.CategoryId
JOIN OrderDetail od ON p.Id = od.ProductId
GROUP BY c.Id, c.CategoryName
ORDER BY OrderedProductsCount DESC;
🍬 Лидер: Confections (Сладости) — 13 продуктов (100% каталога)
ЗАДАНИЕ 5
Какая доставка доставила наибольшее количество заказов?
Ход мысли:
В заказе за курьерскую службу отвечает поле ShipVia (1, 2 или 3). Это внешний ключ на таблицу служб доставки Shipper. Соединяем их по условию Shipper.Id = Order.ShipVia, группируем по названию компании и сортируем по числу выполненных рейсов. 
SELECT 
    s.CompanyName,
    COUNT(o.Id) AS OrdersDelivered,
    ROUND(COUNT(o.Id) * 100.0 / (SELECT COUNT(*) FROM "Order"), 2) AS MarketShare
FROM Shipper s
JOIN "Order" o ON s.Id = o.ShipVia
GROUP BY s.Id, s.CompanyName
ORDER BY OrdersDelivered DESC;
🚚 Лидер: Federal Shipping (Id=3) — 5 654 заказа (33.62% рынка)

🎓 6. Тренажер к защите (Вопросы преподавателя)
1. Почему в SQLite таблицу Order обязательно оборачивать в кавычки ("Order")?
А) Это требование стандарта ANSI SQL для всех таблиц без исключения
Б) Слово ORDER зарезервировано синтаксисом SQL (оператор ORDER BY)
В) Потому что таблица хранит больше 10 000 строк
Верно! Без кавычек парсер SQL решит, что вы пытаетесь выполнить сортировку ORDER BY, и выбросит SyntaxError.
2. Что произойдет, если в формуле выручки проигнорировать столбец Discount?
А) Запрос завершится ошибкой деления на ноль
Б) Выручка будет завышена на сумму скидок (Gross вместо Net)
В) Результат не изменится, так как скидка везде равна нулю
Именно! Поле Discount хранит скидку в долях (0.05, 0.15...). Напитки без скидки дают $99.76 млн, а реальная чистая выручка со скидкой — $93.62 млн (разница $6.14 млн!).
3. Чем COUNT(CustomerId) отличается от COUNT(DISTINCT CustomerId)?
А) Ничем, это полные синонимы
Б) Первый считает все строки (число покупок), а второй отсекает повторы клиентов
В) Второй считает только клиентов с подтвержденным паспортом
Отлично! В таблице 16 818 заказов, но уникальных покупателей всего 95.
