1. Таблицы с прямой адресацией (Direct Address Tables)

Фундаментальная идея: если ключ является неотрицательным целым числом, мы используем сам ключ как непосредственный индекс массива памяти:

Index = Key  &implies;  T[Key] = Value
⚡ Плюсы прямой адресации
  • O(1) в худшем случае: поиск, вставка, удаление и обновление выполняются ровно за 1 обращение к ячейке памяти.
  • Полное отсутствие коллизий: каждый ключ владеет изолированной ячейкой.
⚠️ Критические недостатки
  • Разреженность и взрыв памяти: Универсум возможных ключей $U$ на много порядков превышает реальный набор ключей $K$. Для телефонного справочника из 10-значных номеров требуется массив на $10^{10}$ ячеек (~80 ГБ памяти при 100 записях).
  • Нечисловые ключи: Строки, ФИО, паспортные данные, названия товаров нельзя использовать без преобразования.
  • Упорядоченные массивы: Если хранить ключи плотно в отсортированном массиве, вставка требует $O(n)$ сдвигов.
Рис 1. Сжатие ключей из универсума U в компактную хеш-таблицу размера m. По принципу Дирихле при |U| > m коллизии неизбежны.

2. 3 Классических Метода построения Хеш-функций

На лекции подробно разобраны три фундаментальных математических подхода:

1. Метод деления (Division Method)

h(k) = k mod m

Простейший в реализации способ. Однако результат критически зависит от выбора размера таблицы $m$:

Чего категорически нельзя делать:
  • Нельзя выбирать $m = 2^p$ (в этом случае $h(k)$ зависит исключительно от младших $p$ бит числа $k$, игнорируя старшие).
  • Нельзя выбирать $m = 10^p$ (хеш зависит только от последних десятичных цифр).
Правило: $m$ выбирается как простое число, максимально удаленное от степеней двойки и десятки.

2. Метод умножения (Multiplication Method) — КЛЮЧ К ЛАБОРАТОРНОЙ РАБОТЕ №1!

h(k) = ⌊ m · ((k · A) mod 1) ⌋

где $0 < A < 1$ — вещественная константа. Операция $(k \cdot A) \bmod 1$ означает выделение дробной части произведения:

(k · A) mod 1 = (k · A) - ⌊ k · A ⌋

Согласно Дональду Кнуту, идеальное распределение достигается при константе, связанной с золотым сечением:

A = (√5 - 1) / 2 ≈ 0.618033988749895...
КАТЕГОРИЧЕСКОЕ ТРЕБОВАНИЕ ЛЕКТОРА К КОДУ ЛР №1:
Запрещено писать константу вручную с округлением (например, float A = 0.618f)! Константа обязана вычисляться строго по формуле:
const double A = (std::sqrt(5.0) - 1.0) / 2.0; double temp = key * A; double frac = temp - std::floor(temp); int hashIndex = static_cast<int>(std::floor(m * frac));
Преимущество метода умножения: величина $m$ больше не обязана быть простым числом (может быть даже степенью двойки $m = 2^p$).

3. Метод середины квадрата (Mid-Square Method)

Ключ возводится в квадрат ($k^2$), а затем из середины двоичного представления извлекаются $r$ бит, где $m = 2^r$:

k = 45  &implies;  k² = 2025  &implies;  извлечение средних бит сдвигом ›› и маской &

В C++ для 10-битного адреса ($m = 1024$): (k * k) >> 11 & 0x3FF.

3. Открытая адресация, Правила Пробирования и Маркер Tombstone

В открытой адресации все элементы хранятся в плоском массиве. Последовательность проб при коллизии: $h(k, i)$, где $i = 0, 1, 2, \dots$

Линейное пробирование
h(k, i) = (h(k) + c · i) mod m

При $c = 1$ — шаг 1. Провоцирует первичную кластеризацию. При шаге $c > 1$ (например, $c = 3$) обязательно условие: $\gcd(c, m) = 1$ (взаимная простота), иначе алгоритм зациклится, обойдя лишь часть таблицы!

Двойное хеширование
h(k, i) = (h₁(k) + i · h₂(k)) mod m

Вторая функция $h_2(k)$ определяет индивидуальный шаг. Требование: $h_2(k) > 0$ и $\gcd(h_2(k), m) = 1$. Практический выбор: $h_2(k) = 1 + (k \bmod (m - 1))$ при простом $m$.

Конечный автомат состояния ячейки (Tombstone):

Статус ячейки Числовой код Поведение при ПОИСКЕ (Search) Поведение при ВСТАВКЕ (Insert)
EMPTY 0 СТОП: элемент гарантированно отсутствует Вставка разрешена: пишем ключ, ставим `OCCUPIED`
OCCUPIED 1 Сравнение ключа; при несовпадении шаг $i = i + 1$ Коллизия; переход к следующей пробе $i = i + 1$
DELETED (Tombstone ⚰️) 2 НЕЛЬЗЯ ОСТАНАВЛИВАТЬСЯ! Шаг $i = i + 1$ Вставка разрешена: ячейка перезаписывается
Порог попыток (Limit of Probes $K$): Чтобы защитить алгоритм от бесконечного цикла при заполнении, в цикле пробирования задается лимит $K$ (например, $K = m$ или $K = 10$). При превышении $K$ инициируется динамическое рехеширование ($m \to 2m$).

5. Организация данных для поиска по вторичным ключам

Когда поиск требуется не по первичному ID, а по вторичным признакам (теги, слова, категории), применяются две архитектуры:

А. Инвертированный индекс (Inverted Index)

Первичные и вторичные ключи меняются местами. Ключом выступает слово/тег, а значением — список идентификаторов документов:

"алгоритм" → [Doc 1, Doc 4, Doc 9]
"хеш" → [Doc 1, Doc 2, Doc 4]
  • Поиск документов по слову занимает $O(1)$ без перебора коллекции.
  • Требует дополнительной памяти и фоновой переиндексации.
Б. Битовые карты (Bitmap Index)

Двумерная бинарная матрица: строки — ключевые слова, столбцы — документы. `1` означает наличие слова, `0` — отсутствие.

Слово A: 1 0 1 1 0 0
Слово B: 0 1 1 0 1 0
A AND B: 0 0 1 0 0 0 → (Только Doc 3!)
  • Запросы `AND`, `OR`, `NOT` выполняются за 1 такт CPU через побитовые инструкции.
  • Минус: разреженность при большом словаре (расход RAM на нули).

// Эталонная реализация метода умножения Кнута для Лабораторной №1 #include <cmath> #include <cstddef> size_t knuthMultiplicationHash(size_t key, size_t m) { // Константа золотого сечения (√5 - 1) / 2 const double A = (std::sqrt(5.0) - 1.0) / 2.0; double val = static_cast<double>(key) * A; double fractional_part = val - std::floor(val); return static_cast<size_t>(std::floor(static_cast<double>(m) * fractional_part)); }
