1. Таблицы с прямой адресацией (Direct Address Tables)

Фундаментальная идея: если ключ является неотрицательным целым числом, мы можем использовать сам ключ как непосредственный индекс массива:

Index = Key  &implies;  T[Key] = Value
⚡ Преимущества
  • O(1) в худшем случае: чтение, запись и удаление занимают ровно 1 машинную команду чтения памяти по смещению.
  • Никаких коллизий: каждый ключ гарантированно владеет уникальной ячейкой.
⚠️ Критические недостатки
  • Катастрофическая разреженность памяти: Универсум возможных ключей U огромен по сравнению с реальным множеством K. Для 10-значных телефонных номеров нужен массив на 10¹⁰ ячеек (~80 ГБ RAM для 100 записей).
  • Нечисловые ключи: Строки, UUID, составные структуры не могут быть прямым индексом без отображения.
  • Вставка в упорядоченный массив: Если сжимать данные в плотный массив, вставка требует O(n) сдвигов памяти.

2. Концепция Хеширования и Принцип Дирихле

Хеш-таблица — структура данных, в которой индекс массива для сохранения записи вычисляется математической функцией:

h: U → {0, 1, ..., m - 1}

где U — универсум всех возможных ключей, а m — фактический размер хеш-таблицы.

Математическая неизбежность коллизий (Принцип Дирихле):
Если число возможных ключей |U| строго больше числа ячеек в таблице m (|U| > m), то не существует такой хеш-функции, которая гарантировала бы отсутствие коллизий для всех входных наборов. По принципу Дирихле хотя бы два ключа обязательно попадут в одну ячейку:
h(k₁) = h(k₂)  при  k₁ ≠ k₂

Конвертация нечисловых ключей (Полиномиальное хеширование строк)

Для строк и составных объектов вычисляется полиномиальный хеш по основанию простого числа p (обычно p = 31 или p = 53):

h(s) = ( ∑ s[i] · pⁱ ) mod m  ≡  (s[0] + s[1]·p + s[2]·p² + ...) mod m
Инженерный подводный камень (Integer Overflow): В C++ / Java прямое вычисление pⁱ мгновенно переполняет 64-битный тип. Хеш должен считаться по схеме Горнера с взятием остатка на каждом шаге: hash = (hash * p + s[i]) % m;

3. Методы разрешения коллизий

Существуют две архитектурно противоположные парадигмы:

А. Открытая адресация (Open Addressing)

Все элементы хранятся внутри самого плоского массива. Никаких связных списков. При коллизии ячейка ищется по правилу пробирования:

  • Линейное: h(k, i) = (h(k) + i) mod m (шаг 1). Провоцирует первичную кластеризацию.
  • Квадратичное: h(k, i) = (h(k) + c₁ i + c₂ i²) mod m. Устраняет первичные кластеры, но сохраняет вторичные.
  • Двойное хеширование: h(k, i) = (h₁(k) + i · h₂(k)) mod m. Лучшее рассеивание.
Проблема Tombstone (Удаление): Нельзя просто очистить ячейку (записать NULL)! Поиск последующих элементов, попавших в коллизию с этим ключом, остановится на пустой ячейке и вернет false. Необходим маркер DELETED (tombstone).
Б. Метод цепочек (Separate Chaining)

Каждая ячейка таблицы T[i] содержит указатель на связный список (или динамический вектор) записей с одинаковым хешем.

  • Вставка: Добавление в голову списка за O(1).
  • Удаление: Стандартное удаление узла из связного списка (O(1) при известном указателе). Никаких проблем с Tombstone.
  • Коэффициент заполнения α: Может легко превышать 1.0 (например, α = 3.5 означает в среднем 3.5 узла на корзину).
Hardware-налог (Cache Locality): Узлы связного списка разбросаны в куче (heap). Каждый переход по указателю next вызывает Cache Miss в L1/L2 процессора, плюс накладные расходы на указатель (8 байт на 64-bit системе на каждый узел).
Рис 2. Без маркера DELETED разрывается поисковая цепочка для всех элементов, попавших в коллизию позже.

5. Коэффициент заполнения (Load Factor) и Рехеширование

Эффективность любой хеш-таблицы определяется коэффициентом заполнения:

α = n / m

где n — фактическое число сохраненных записей, m — емкость таблицы (количество корзин).

Открытая адресация: α ≤ 1.0

Так как ячейки физически ограничены размером m, значение α принципиально не может превысить 1.0.

Критический порог: При α ≥ 0.65 .. 0.70 среднее число проб на операцию лавинообразно растет из-за слияния первичных кластеров. Среднее время деградирует до O(n).

Метод цепочек: α может быть > 1.0

При методе цепочек α отражает математическое ожидание длины связного списка в ячейке. Даже при α = 2.0 поиск требует в среднем 1 + α / 2 = 2 операции.

Процесс Рехеширования (Dynamic Rehashing)

Когда порог α ≥ 0.65 превышен, хеш-таблица выполняет перестройку:

  1. Выделяется новый непрерывный массив памяти размера m_new ≈ 2m (обычно выбирается ближайшее простое число, чтобы хеш-функция k mod m равномернее перемешивала биты).
  2. Нельзя просто скопировать память! Так как новое значение m_new изменилось, для каждого существующего ключа вычисляется новый индекс: h_new(k) = k mod m_new.
  3. Все элементы заново вставляются в новую таблицу (O(n) амортизированная стоимость). Все ячейки с маркером DELETED удаляются навсегда, освобождая память.
