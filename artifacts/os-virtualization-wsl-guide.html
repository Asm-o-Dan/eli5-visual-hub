ОС, Виртуализация и WSL: Наглядный гид

Ментальная модель на пальцах: как работают операционные системы, чем отличаются гипервизоры 1 и 2 типа, почему WSL2 быстрее VirtualBox и зачем нужны снэпшоты.

❌ Заблуждение новичка
  • ⛔ «Виртуальная машина — это просто программа в окне, как браузер или игра».
  • ⛔ «WSL — это полноценный эмулятор Linux или обычная виртуалка».
  • ⛔ «Динамический диск VDI сам сжимается обратно, когда удаляешь файлы».
  • ⛔ «Если отдать ВМ 90% всей памяти ПК, она будет летать быстрее».
✅ Инженерная реальность
  • ⚡ ВМ — это аппаратная изоляция: процессор сам переключает контексты гостевой ОС через Intel VT-x / AMD-V.
  • ⚡ WSL2 — это микро-виртуалка: настоящее ядро Linux нативно живет под Hyper-V с динамической памятью.
  • ⚡ Диски и снэпшоты — это дельта-деревья: базовый диск запечатывается на чтение, а изменения пишутся в новый файл.
  • ⚡ Баланс ресурсов: удушение хоста Windows памятью убивает и саму ВМ из-за дефицита дискового кэша.

Физическая установка ОС на компьютер

Операционная система работает непосредственно с контроллерами накопителей, памятью и графическим ядром.

Плюсы:
100% производительность CPU/GPU, минимальные задержки дискового ввода-вывода (I/O).
Минусы:
Нет изоляции, переустановка долгая, нельзя легко перенести систему на другой ПК одним файлом.

Гипервизор 1 типа (Bare-Metal)

Устанавливается прямо на серверное железо вместо обычной ОС. Примеры: VMware ESXi, Proxmox VE, Microsoft Hyper-V Server.

Плюсы:
Оверхед менее 2-3%. Максимальная надежность корпоративного класса. Прямой доступ к аппаратной виртуализации.
Минусы:
Требует отдельный выделенный сервер. Не имеет привычного рабочего стола для повседневного домашнего использования.

Гипервизор 2 типа (Hosted)

Обычная программа, запускаемая внутри Windows или macOS. Примеры: Oracle VirtualBox, VMware Workstation Player.

Плюсы:
Идеально для учебы и песочниц. Удобный графический интерфейс, моментальные снимки, поддержка любых гостевых ОС.
Минусы:
Потери производительности до 15-20% из-за двойного стека ядер. Высокий оверхед по памяти.

WSL 1: Программная эмуляция (LXCore)

В WSL 1 нет настоящего ядра Linux. Системные вызовы (syscalls) транслируются в вызовы ядра Windows NT на лету через мост драйверов.

Плюсы:
Мгновенная работа с файлами диска C:, нет накладных расходов на виртуализацию ядра.
Минусы:
Неполная совместимость (многие системные вызовы Linux падали с ошибкой), невозможно запустить Docker без сторонней ВМ.

WSL 2: Нативное микроядро Hyper-V

Полноценное, легковесное настоящее ядро Linux, работающее в изолированной микро-виртуалке гипервизора Hyper-V с файловой системой ext4 в VHDX.

Плюсы:
100% совместимость с системными вызовами, нативный Docker, динамическое освобождение RAM, старт за 1 секунду.
Минусы:
Доступ к файлам диска Windows через /mnt/c/ идет через протокол 9P и работает медленнее, чем внутри ext4.

Как файлы `.vdi` обманывают гостевую ОС и как создается дельта-цепочка снимков.

🐧 Дистрибутивы Linux и магия LTS

Дистрибутив = Ядро Linux + Утилиты GNU + Пакетный менеджер + Окружение рабочего стола.

  • Ubuntu Дружелюбный, идеален для новичков, десктопов и Docker.
  • Debian «Скала стабильности»: строгий отбор пакетов для серверов.
  • RHEL Корпоративный стандарт для банков и крупных предприятий.
Что такое LTS (Long Term Support)? Релизы выходят раз в 2 года (20.04, 22.04, 24.04) и поддерживаются 5 лет. Пакеты не ломают API — код, написанный сегодня, гарантированно запустится через 4 года.

🔐 Удаленный доступ: SSH и Порт 22

SSH (Secure Shell) — протокол удаленного защищенного администрирования. Заменяет небезопасный старый Telnet, передававший пароли открытым текстом.

  • Стандартный порт: 22 / TCP.
  • PuTTY: Графический SSH-клиент для Windows для подключения к консоли Linux.
  • Проброс портов (Port Forwarding): В VirtualBox нужно пробросить хостовый порт 2222 → 22 гостя для доступа из Windows.
ssh user@127.0.0.1 -p 2222 # вход из терминала Windows

⚖️ Золотое правило ресурсов (RAM и Диск)

Как распределять ресурсы физического компьютера:

  • Ubuntu Server (CLI): 1-2 GB RAM, 15-20 GB Disk.
  • Ubuntu Desktop (GUI): 4-8 GB RAM, 40-50 GB Disk.

⚠️ Ловушка жадности: Если на хосте всего 16 GB, а вы отдадите ВМ 14 GB — хостовая Windows начнет сбрасывать свой кэш в своп. В итоге зависнут обе системы одновременно!

💿 Образ диска (ISO): Флешка в файле

ISO — это посекторный снимок оптического накопителя (стандарты ISO 9660 / UDF).

  • В ВМ он вставляется в эмулируемый CD-привод.
  • Виртуальный BIOS стартует с ISO → запускает инсталлятор → размечает виртуальный диск .vdi → копирует ядро и пакеты.
  • После установки ISO извлекается, чтобы ВМ грузилась уже с VDI.

Используйте WSL2 для повседневной разработки (Node/Python/Docker/C++), а VirtualBox — когда нужен чистый независимый дистрибутив с изоляцией сети.
