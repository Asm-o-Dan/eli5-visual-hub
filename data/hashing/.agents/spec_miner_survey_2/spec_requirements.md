## 2. Архитектура Требований R1: Главный Лист («Панель_Управления»)

### 2.1. Инициализация и разметка листа (`setupControlSheet`)
- Главный лист проекта именуется строго: **`«Панель_Управления»`**.
- Функция `setupControlSheet()` форматирует или пересоздает лист с двухблочной компоновкой:
  - **Слева (столбцы A..G)**: Таблица исходных данных (30 эталонных или сгенерированных записей).
  - **Столбец-разделитель (столбец H)**: Буферная пустая колонка (ширина 30 px).

Таблица исходных данных методички (Таблица 1):
1. **Столбец A (I)**: Ф.И.О. владельца (строка, ширина ~220 px).
2. **Столбец B (II)**: Дата рождения (формат `дд.мм.гггг`, ширина ~110 px).
3. **Столбец C (III)**: **Номер телефона** (формат `xx-xxx-xx`, ширина ~120 px) — **Ключевое поле Варианта 3**.
4. **Столбец D (IV)**: Серия и номер паспорта (`xxxx xxxxxx`, ширина ~140 px).
5. **Столбец E (V)**: Адрес прописки (строка, ширина ~280 px).
6. **Столбец F (VI)**: Номер банковского счета (20 цифр, ширина ~200 px).
7. **Столбец G (VII)**: Остаток денег на счете (денежный формат с копейками, ширина ~130 px).

- **Стилизация шапки (Строка 1, A1:G1)**:
  - Фон: `#1e293b` (Slate-800).
  - Шрифт: белый `#ffffff`, полужирный (Bold), выравнивание по центру, перенос текста (Wrap).

- **Стилизация строк данных (Строки 2..N+1)**:

    - Значение по умолчанию: `val => parseInt(String(val).replace(/\D/g, ''), 10)`
    - Шрифт: `Consolas`, 10 pt, цвет `#0f172a`, фон `#f8fafc`, рамка `#94a3b8`.
    - Оператор может редактировать этот код прямо в ячейке Google Таблицы.

### 2.4. Динамическое исполнение `numKey` через `new Function()`
- Скрипт GAS считывает строковое содержимое ячейки кода `numKey`.
- Компиляция и исполнение производятся динамически:
  ```javascript
  function compileNumKey(codeStr) {
    const raw = String(codeStr || '').trim();
    if (!raw) {
      return (val) => parseInt(String(val).replace(/\D/g, ''), 10);
    }
    // Поддержка стрелочных функций (val => ...) и стандартных (function(val) { ... })
    if (raw.startsWith('function') || raw.startsWith('(') || raw.includes('=>')) {
      return new Function('return (' + raw + ');')();
    }
    // Поддержка прямого тела функции
    return new Function('val', raw);
  }
  ```
- **Защита и санитизация**:
  - Оборачивание вызова в `try...catch`.
  - При возникновении ошибки парсинга или исполнения генерируется понятное модальное предупреждение `ui.alert` с указанием исходного текста и ошибки JS.
  - Результат работы функции гарантированно приводится к неотрицательному целому числу:
    `const k = Math.floor(Math.abs(Number(fn(val)))) || 0;`

На листе «Панель_Управления» размещаются 3 графических элемента-кнопки (через Drawing или меню):

## 3. Архитектура Требований R2: Стресс-Тест и Встроенная Диаграмма

### 3.1. Алгоритм функции `runStressTest()`
1. Считывание параметров $N$, $M$ и пользовательского кода `numKey` с листа «Панель_Управления».
2. Генерация $N$ синтетических телефонных номеров формата `xx-xxx-xx` (где $x \in [0..9]$).
3. Извлечение численного ключа $k = \text{numKey}(\text{phone})$.
4. Вычисление первичного хеша Кнута для каждого ключа:
   $$h(k) = \lfloor M \cdot ((k \cdot A) \bmod 1) \rfloor$$
   где $A = \frac{\sqrt{5}-1}{2} \approx 0.618033988749895$.
5. Агрегация вектора частот попаданий: $\text{freq}[s]$ для $s \in [0..M-1]$.

### 3.2. Статистические метрики распределения
Скрипт производит точный математический расчет и выводит сводную карточку метрик:
1. **Средняя частота (коэффициент загрузки $\alpha$)**:
   $$\bar{f} = \frac{N}{M}$$
2. **Максимальное число коллизий в одном бакете**:
   $$f_{\max} = \max_{0 \le s < M} \text{freq}[s]$$
3. **Количество свободных (пустых) слотов**:
   $$S_{\text{empty}} = \sum_{s=0}^{M-1} [\text{freq}[s] = 0]$$
4. **Критерий согласия Пирсона $\chi^2$ (Chi-Square Goodness-of-Fit)**:
   Оценивает близость эмпирического распределения к теоретическому равномерному:
   $$\chi^2 = \sum_{s=0}^{M-1} \frac{(O_s - E)^2}{E} = \sum_{s=0}^{M-1} \frac{(\text{freq}[s] - N/M)^2}{N/M}$$
   где $O_s = \text{freq}[s]$ — наблюдаемая частота слота, $E = \frac{N}{M}$ — математическое ожидание.
   - Число степеней свободы: $df = M - 1$.
   - При хорошей равномерности хеш-функции $\chi^2 \approx M - 1$.

### 3.3. Таблица частот на листе «Панель_Управления»
- Размещается в свободной зоне справа (например, столбцы I..K, строки 14..14+M):
  - Столбец I: Слот $s$ ($0..M-1$).
  - Столбец J: Частота $O_s$ (число попаданий).
  - Столбец K: Теоретическое ожидание $E_s = N/M$.
- Карточка метрик размещается над/рядом с таблицей с понятными цветовыми индикаторами.

### 3.4. Встроенная столбчатая диаграмма (`EmbeddedChart`)
- Тип диаграммы: `SpreadsheetApp.ChartType.COLUMN`.
- Источник данных: диапазон таблицы частот (Слот vs Частота).
- Настройки:
  - Заголовок: `«Гистограмма распределения хеш-значений (N={N}, M={M})»`.
  - Ось X (горизонтальная): `«Слот хеш-таблицы (0..M-1)»`.
  - Ось Y (вертикальная): `«Частота попаданий»`.
  - Легенда: `None` (без легенды для чистоты графика).
  - Цветовое оформление: фирменный индиго-синий `#4f46e5`.
- **Жизненный цикл диаграммы**:
  - Перед созданием диаграммы скрипт проверяет существующие диаграммы на листе:
    `sheet.getCharts().forEach(c => sheet.removeChart(c));`
  - Это предотвращает наслоение и дублирование диаграмм при повторных запусках стресс-теста.

## 4. Архитектура Требований R3: Шаблонизация и Генерация Листа Хеш-Таблицы

### 4.1. Скрытый эталонный шаблон (`_Шаблон_Таблицы_`)
- Имя листа: строго **`_Шаблон_Таблицы_`**.
- Состояние: скрыт от пользователя штатным методом `sheet.hideSheet()`.
- Назначение: содержит эталонную структуру шапки, стилизацию границ, шрифты (`Consolas`, `Inter`), выравнивания и форматы данных.
- Создается автоматически при вызове `setupControlSheet()`, если отсутствует.

### 4.2. Алгоритм клонирования и генерации (`buildHashTableFromTemplate`)
1. Считывание актуальных настроек с «Панель_Управления»:
   - Размер таблицы $M$ (по умолчанию 60).
   - Шаг линейного пробирования $\text{step}$ (по умолчанию 1).
   - Предел проб $\text{fallback}$ (по умолчанию 60).
   - Метод: «Открытая адресация» или «Метод цепочек».
   - Код `numKey`.
2. Считывание всех строк данных из левой таблицы (A..G).
3. Определение целевого имени листа:
   - Для открытой адресации: `Хеш_Таблица_Линейное_M{M}` (например, `Хеш_Таблица_Линейное_M60`).
   - Для метода цепочек: `Хеш_Таблица_Цепочки_M{M}`.
   - Если лист с таким именем уже существует, он перезаписывается (или очищается и обновляется).
4. Клонирование листа-шаблона:
   `const newSheet = templateSheet.copyTo(ss).setName(targetSheetName).showSheet();`
5. Сохранение конфигурации в метаданных документа (`DocumentProperties`):
   - `ACTIVE_TABLE_SHEET`: имя сгенерированного листа.
   - `ACTIVE_M`: значение $M$.
   - `ACTIVE_STEP`: значение $\text{step}$.
   - `ACTIVE_FALLBACK`: значение $\text{fallback}$.
   - `ACTIVE_METHOD`: выбранный метод.

### 4.3. Режим «Открытая адресация» (Линейное пробирование)
- Размерность: строго $M$ строк (слоты $0..M-1$).
- Статусы слотов:
  - **`EMPTY`** — слот свободен, никогда не занимался.
  - **`OCCUPIED`** — слот занят актуальной записью.
  - **`DELETED`** — надгробие (Tombstone): элемент был удален, но цепочка проб не должна прерываться.
- **Формула пробирования**:
  $$h(k, i) = (h_1(k) + i \cdot \text{step}) \bmod M, \quad i = 0, 1, 2, \dots, (\text{fallback} - 1)$$
  где $h_1(k) = \lfloor M \cdot ((k \cdot A) \bmod 1) \rfloor$.
- **Порядок вставки записи**:
  1. Для каждой записи вычисляется $k = \text{numKey}(\text{phone})$ и первичный хеш $h_1(k)$.
  2. Последовательно проверяются слоты $h(k, i)$ при $i = 0, 1, \dots$:
     - Если слот имеет статус `EMPTY` или `DELETED` — запись размещается в этот слот.
     - Фиксируется число затраченных проб: $P = i + 1$.
     - Фиксируется полная трасса проб: $[h(k,0) \to h(k,1) \to \dots \to \text{slot}]$.
     - Если $i \ge \text{fallback}$ — генерация прерывается с ошибкой переполнения.
- **Столбцы сгенерированной таблицы**:
  1. `Слот (0..M-1)`
  2. `Статус` (`EMPTY`, `OCCUPIED`, `🪦 DELETED`)
  3. `Ключ (Номер телефона xx-xxx-xx)`
  4. `Ф.И.О. владельца`
  5. `Исходная строка №`
  6. `Первичный хеш h1(k)`
  7. `Число проб (Probes)`
  8. `Трасса пробирования (Trace)`
- **Цветовое дифференцирование строк**:
  - `EMPTY`: мягкий серый `#f8fafc`, приглушенный текст `#94a3b8`.
  - `OCCUPIED` без коллизий ($P = 1$): белый фон `#ffffff`, бейдж статуса зеленый `#dcfce7` (текст `#166534`, Bold).
  - `OCCUPIED` с коллизией ($P > 1$): мягкий янтарный фон `#fffbeb`, бейдж статуса желтый `#fef3c7` (текст `#b45309`), число проб выделено красным `#dc2626` Bold.
  - `DELETED`: розовато-красный `#fee2e2`, текст темно-красный `#991b1b`, бейдж `🪦 DELETED`.

### 4.4. Режим «Метод цепочек» (Separate Chaining)
- Размерность: $M$ бакетов ($0..M-1$).
- Каждый бакет содержит связный список элементов, попавших в него при первичном хешировании:
  $$h(k) = \lfloor M \cdot ((k \cdot A) \bmod 1) \rfloor$$
- Структура строки:
  - Слот бакета ($0..M-1$).
  - Хеш $h(k)$.
  - Длина цепочки (число элементов).
  - Визуализация связного списка: `[#row] «телефон» (Ф.И.О.) [глуб: 1] ➜ [#row] ...`
  - Статус: `Пусто (0)` / `1 элемент (без коллизий)` / `K элементов (КОЛЛИЗИЯ)`.

### 4.5. Интерактивные операции на сгенерированном листе
На сгенерированном листе создаются кнопки или пункты меню для интерактивной работы:

1. **Кнопка «➕ Добавить запись» (`insertRecordInteractive`)**:
   - Открывает модальный диалог ввода:
     - Номер телефона (например, `55-777-88`).
     - Ф.И.О. владельца (например, `Кузнецов Петр Сергеевич`).
   - Вычисляет $k = \text{numKey}(\text{phone})$ и $h_1(k)$.
   - Выполняет поиск первого свободного слота (`EMPTY` или `DELETED`) по формуле $h(k, i) = (h_1(k) + i \cdot \text{step}) \bmod M$.
   - Записывает данные, меняет статус на `OCCUPIED`, записывает $P$ и трассу.
   - Выделяет добавленную строку `sheet.setActiveRange(...)` и выдает информационный `ui.alert`.

2. **Кнопка «🗑️ Удалить запись» (`deleteRecordInteractive`)**:
   - Открывает диалог ввода номера телефона для удаления.
   - Производит пробирование слотов:
     - Если встречает `EMPTY`: поиск завершается, запись отсутствует в таблице.
     - Если встречает `DELETED`: **не останавливается**, а продолжает проверять следующие шаги трассы.
     - Если встречает `OCCUPIED` и ключ совпадает:
       - Слот переводится в статус **`🪦 DELETED`** (установка надгробия Tombstone).
       - Данные ключа очищаются или помечаются как удаленные `[Удален: xx-xxx-xx]`.
       - Выделяется строка надгробия и выдается пояснительное уведомление.

### 4.6. Встроенный автофильтр Google Sheets (`createFilter`)
- На таблицу слотов автоматически устанавливается нативный автофильтр:
  `range.createFilter();`
- **Защита от ошибки `There is already a filter on this sheet`**:
  Скрипт проверяет наличие фильтра перед созданием:
  ```javascript
  const existingFilter = sheet.getFilter();
  if (existingFilter) {
    existingFilter.remove();
  }
  tableRange.createFilter();
  ```
- **Пользовательские сценарии использования автофильтра**:
  - Быстрый поиск конкретного телефона через стандартное окно поиска столбца C.
  - Фильтрация по статусу: показать только `OCCUPIED`, только `DELETED` или только `EMPTY`.
  - Фильтрация по числу проб: показать все слоты с коллизиями ($P > 1$).

## 7. Математический Аппарат и Формулы

### 7.1. Мультипликативное хеширование Д. Кнута
$$h_1(k) = \left\lfloor M \cdot \left( (k \cdot A) \bmod 1 \right) \right\rfloor$$
- **Константа золотого сечения**:
  $$A = \frac{\sqrt{5} - 1}{2} \approx 0.6180339887498948482...$$
- **Свойства**:
  - Обеспечивает псевдослучайное квазиравномерное рассеивание последовательных и кластеризованных ключей.
  - Дробная часть $(k \cdot A) \bmod 1 \in [0, 1)$.
  - Значение $h_1(k) \in \{0, 1, \dots, M-1\}$.

### 7.2. Линейное пробирование с произвольным шагом и ограничителем
Последовательность проверяемых слотов для ключа $k$:
$$h(k, i) = (h_1(k) + i \cdot \text{step}) \bmod M, \quad i \in [0, \text{fallback} - 1]$$
- При $\text{step} = 1$: стандартное линейное пробирование $h(k, i) = (h_1(k) + i) \bmod M$.
- Число шагов $i$ ограничено константой $\text{fallback} \le M$, что исключает зацикливание даже если $\gcd(\text{step}, M) > 1$.

### 7.3. Статистический критерий согласия $\chi^2$ (Пирсона)
$$\chi^2 = \sum_{s=0}^{M-1} \frac{(O_s - E)^2}{E}$$
где:
- $O_s$ — количество попаданий в слот $s$ ($\sum_{s=0}^{M-1} O_s = N$).
- $E = \frac{N}{M}$ — математическое ожидание числа попаданий в один слот при идеальной равномерности.
- Преобразованная вычислительная формула (минимизирует накопление погрешности):
  $$\chi^2 = \frac{M}{N} \sum_{s=0}^{M-1} O_s^2 - N$$
