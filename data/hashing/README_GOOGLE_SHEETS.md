## ⚡ Архитектура решения

### 1. Главный лист «Панель_Управления» (R1)
Инициализируется функцией `setupControlSheet()` и разделен на две функциональные зоны:
- **Левый блок (Столбцы A..G)**: Таблица исходных данных
  - `A`: Ф.И.О. владельца
  - `B`: Дата рождения (`дд.мм.гггг`)
  - `C`: **Номер телефона (`xx-xxx-xx`) — Ключ Варианта 3**
  - `D`: Серия и номер паспорта
  - `E`: Адрес прописки
  - `F`: Номер банковского счета (20 цифр)
  - `G`: Остаток денег на счете
- **Разделитель (Столбец H)**: Буферная колонка шириной 30 px.
- **Правый блок (Столбцы I..N)**: Блок параметров и динамического кода
  - `J3` ($M$): Размер хеш-таблицы (по умолчанию `60`)
  - `J4` ($step$): Шаг линейного пробирования (по умолчанию `1`)
  - `J5` ($fallback$): Максимальное число проб до остановки / overflow (по умолчанию `60`)
  - `J6` (Метод): Выпадающий список Data Validation (`["Открытая адресация", "Метод цепочек"]`)
  - `J7` ($N$): Количество записей для генерации / стресс-теста ($1 \le N < 1000$, по умолчанию `30`)
  - `I10:N10` (`numKey`): **Редактируемый JS-код функции извлечения числового ключа**:
    ```javascript
    val => parseInt(String(val).replace(/\D/g, ''), 10)
    ```
    Оператор может изменить код прямо в ячейке; скрипт выполняет его динамически через `new Function()`, с безопасным откатом на дефолт при ошибках.

### 2. Стресс-тест и встроенная столбчатая диаграмма (R2)
Запускается функцией `runStressTest()` (кнопка «📈 Запустить стресс-тест»):
1. Генерирует $N$ синтетических телефонных номеров формата `xx-xxx-xx`.
2. Извлекает ключи через скомпилированную функцию `numKey` и хеширует мультипликативным методом Кнута:
   $$h(k) = \lfloor M \cdot ((k \cdot A) \bmod 1) \rfloor, \quad A = \frac{\sqrt{5}-1}{2} \approx 0.618033988749895$$
3. Заполняет таблицу частот попаданий по слотам $0..M-1$ на листе «Панель_Управления».
4. Рассчитывает статистические метрики качества:
   - Средняя частота: $\bar{f} = N / M$
   - Максимум коллизий в одном бакете: $\max(f)$
   - Число пустых слотов: $S_{\text{empty}}$
   - Критерий согласия Пирсона: $\chi^2 = \sum_{s=0}^{M-1} \frac{(f_s - N/M)^2}{N/M}$
5. Создает или обновляет встроенную гистограмму Google Sheets (`EmbeddedChart` типа `COLUMN`), удаляя старые графики для исключения дублирования.

### 3. Скрытый шаблон и клонирование таблицы (R3)
- Скрытый эталонный лист `_Шаблон_Таблицы_` создается автоматически при инициализации.
- Функция `buildHashTableFromTemplate()` (кнопка «⚡ Построить хеш-таблицу»):
  1. Клонирует шаблон в новый рабочий лист (например, `Хеш_Таблица_Линейное_M60` или `Хеш_Таблица_Цепочки_M60`).
  2. Заполняет слоты таблицы данными:
     - **Открытая адресация**: слоты $0..M-1$ со статусами `EMPTY`, `OCCUPIED`, `DELETED`, подсчетом числа затраченных проб $P$ и трассой шагов $h(k, i) = (h_1(k) + i \cdot step) \bmod M$ с ограничением `fallback`.
     - **Метод цепочек**: бакеты со связными списками элементов и счетчиками длины цепочки.
  3. Автоматически устанавливает нативный автофильтр Google Sheets (`range.createFilter()`) с предварительной проверкой и удалением старого фильтра.
  4. Поддерживает интерактивные функции:
     - `insertRecordInteractive()`: интерактивный ввод телефона и ФИО с поиском первого свободного слота (`EMPTY` или `DELETED`) и цветовой подсветкой.
     - `deleteRecordInteractive()`: удаление записи по номеру телефона с установкой надгробия **`🪦 DELETED`**, что сохраняет целостность поисковых цепочек.

## 🪦 Инвариант надгробий (Tombstone DELETED)

При удалении записи ячейка не очищается в `EMPTY`, а переводится в статус **`🪦 DELETED`**.
- **Почему это критично**: при линейном пробировании элементы с одинаковым первичным хешем образуют неразрывную цепочку проб. Если удалить промежуточный элемент и очистить ячейку в `EMPTY`, алгоритм поиска посчитает цепочку оконченной и **никогда не найдет элементы**, расположенные дальше по трассе!
- **Поведение алгоритмов**:
  - `Поиск` (`search`): встречая `EMPTY` — останавливается (не найдено); встречая `DELETED` — **продолжает поиск дальше**; встречая `OCCUPIED` — проверяет ключ.
  - `Вставка` (`insert`): может занимать ячейки со статусом `DELETED`, повторно используя память таблицы.
